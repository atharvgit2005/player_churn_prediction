\begin{abstract}
This project presents an end-to-end player churn prediction system built with Streamlit and classical machine learning models for online gaming analytics. The system supports data upload, robust preprocessing, dynamic target handling, multi-model training, evaluation, feature-importance analysis, risk segmentation, and single-player inference. Three classifiers, namely Logistic Regression, Random Forest, and Decision Tree, are trained through a unified preprocessing pipeline with imputation, scaling, and one-hot encoding. In addition to predictive analytics, the application includes an engagement optimization assistant that summarizes player behavior, interprets churn risk, generates retention recommendations, and exports a structured PDF report. The resulting platform combines predictive performance with usability, interpretability, and deployment readiness for retention-focused decision support.
\end{abstract}

\begin{IEEEkeywords}
Player churn, machine learning, Streamlit, classification, feature engineering, model interpretability, engagement optimization.
\end{IEEEkeywords}

\section{Introduction}
Player churn directly affects revenue, engagement, and long-term platform growth in online games and digital products. Early identification of high-risk players enables targeted intervention campaigns such as rewards, recommendations, personalized nudges, and re-engagement flows. In practice, teams need more than a single prediction score; they also need interpretable model outputs, player-level drill-down, and an interface that supports operational decisions. The goal of this project is therefore to build an interactive machine learning application that predicts player churn risk and presents the results through a deployable analytics dashboard.

\section{Related Work}
Customer and player churn prediction is commonly modeled as supervised binary classification, using models such as Logistic Regression, tree-based methods, and ensemble approaches \cite{burez2009churn,verbeke2012new}. Prior work highlights the usefulness of behavioral features and interpretable outputs for operational decisions \cite{huang2012churn}. Our project follows this direction with a practical app-first implementation.

\section{Methodology}

\subsection{Dataset Description}
The dataset (\texttt{online\_gaming\_behavior\_dataset.csv}) contains 40,034 player records and 13 features, including demographics, gameplay behavior, monetization, and progression signals. Representative attributes include age, game genre, play time hours, in-game purchases, sessions per week, average session duration, player level, and achievement count. The target column is \texttt{EngagementLevel}. For churn-style binary modeling, \texttt{Low} engagement is mapped as the positive class (churn = 1), while the remaining engagement levels are mapped to non-churn (0).

\subsection{Preprocessing}
The preprocessing stack includes:
\begin{itemize}
    \item Median imputation + standard scaling for numeric features
    \item Most-frequent imputation + one-hot encoding for categorical features
    \item Optional removal of high-cardinality ID columns from model training
\end{itemize}
A \texttt{ColumnTransformer} ensures consistent preprocessing across all models.

\subsection{Feature Engineering}
An engagement feature is created when session frequency and average session duration are available:
\[
\texttt{engagement\_score} = \texttt{session\_frequency} \times \texttt{avg\_session\_duration}
\]
Risk buckets are defined from predicted churn probability:
Low ($\leq 0.30$), Medium ($0.30$--$0.70$), High ($>0.70$).

\subsection{Models Used}
The training module fits three classifiers:
\begin{itemize}
    \item Logistic Regression
    \item Random Forest
    \item Decision Tree
\end{itemize}
Class-weight balancing is enabled when class imbalance is detected.

\subsection{Training and Validation}
Data is split into train and test sets using an 80/20 split with fixed random seed (\texttt{random\_state=42}) and stratification. Evaluation includes Accuracy, Precision, Recall, F1-score, ROC-AUC, confusion matrix visualization, feature-importance plots, and risk distribution analysis. The final application also includes an assistant module that assembles a structured engagement report from model predictions, player attributes, supporting references, and ethical disclaimers before allowing PDF export.

\subsection{System Interface}
The machine learning pipeline is exposed through a multi-section Streamlit dashboard named \textit{ChurnIQ}. The major interface modules are Data Overview, Model Training, Model Evaluation, Player Risk Analysis, Decision Tree Explorer, and the Engagement Optimization Assistant. The final interface follows a dark analytics dashboard style and is designed to preserve model functionality while improving readability, workflow clarity, and report exportability. Visual refinements were implemented without changing model logic, session-state handling, or preprocessing behavior.

\subsection{Assistant Reporting and Validation}
The Engagement Optimization Assistant extends the predictive workflow from classification to action-oriented reporting. For a selected player, the assistant compiles a report containing six mandatory sections: title block, player behavior summary, churn risk interpretation, engagement and retention recommendations, supporting references, and ethical or user-experience disclaimers. Before PDF generation, a validation layer checks that every required section is present and non-empty. If any section is missing, export is blocked and the user is shown an explicit error message listing the incomplete sections. This design prevents incomplete or misleading reports from being generated.

\subsection{Testing and Reliability}
To preserve existing functionality while adding report export features, automated tests were added using \texttt{pytest}. These tests verify schema completeness for generated reports, graceful handling of missing or noisy player data, successful PDF generation, and the presence of at least one reference entry in both the structured output and exported PDF. This testing layer improves reliability and makes the application more suitable for reproducible academic demonstration.

\subsection{System-Level Outcome}
The final system is not limited to offline model comparison. It supports a complete user workflow consisting of dataset upload, preprocessing, model training, evaluation, player-level risk inspection, decision-tree exploration, assistant-driven recommendation generation, and PDF export. As a result, the project functions both as a machine learning experiment and as a lightweight decision-support application for gaming analytics.

\section{Discussion}
Random Forest achieved the strongest overall balance across the earlier comparison metrics, particularly in accuracy, precision, and F1-score. The final exported Decision Tree evaluation also produced strong results, with an accuracy of 0.947, F1-score of 0.895, and ROC-AUC of 0.997, showing that it remains highly competitive while offering superior interpretability. Logistic Regression produced high recall but lower precision, indicating more false positives and therefore a higher false-alarm rate for retention interventions. Decision Tree remains especially valuable from an interpretability perspective because its behavior can be explained through explicit decision rules and visual tree analysis.

Beyond model quality, the project emphasizes practical usage. The dashboard supports data upload, model comparison, player-level analysis, and assistant-generated retention reporting in a single workflow. This improves the operational usefulness of the system because a retention or product team can move from raw data inspection to actionable recommendations without leaving the application. The PDF export layer further strengthens reproducibility by packaging behavior summary, risk interpretation, recommendations, references, and ethical disclaimers into a portable report. The redesigned interface also improves presentation quality and usability, which is valuable in academic demonstrations where system flow and interpretability matter alongside raw model performance.

The project still has limitations. It is currently evaluated on a single dataset, the binary target is derived from an engagement label rather than direct historical churn labels, and the reported results are based on one train-test split. Future work can include k-fold cross-validation, hyperparameter tuning, temporal holdout validation, calibration analysis for predicted probabilities, and richer recommendation logic driven by domain-specific retention experiments.

\section{Conclusion}
This project delivers a practical churn prediction framework with:
\begin{itemize}
    \item Unified multi-model training
    \item Standardized evaluation and confusion matrix analysis
    \item Feature-importance-based driver interpretation
    \item Risk segmentation and probability visual analytics
    \item Single-player prediction with UI risk badge rendering
    \item Engagement assistant with structured PDF export
    \item Validation and automated testing for report reliability
\end{itemize}
The system is suitable for rapid experimentation and retention-focused decision support in gaming analytics. By combining machine learning pipelines with an interactive user interface and report-generation capabilities, the project demonstrates how predictive models can be translated into practical decision-support tools for player engagement management.
